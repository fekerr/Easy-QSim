Below is an updated version of your `meson.build` file along with guidance on how to modify your logging behavior via the environment. In this updated file we add a custom target for “doit” that always runs (using `build_always: true`) so that you get fresh output each time—even if nothing has changed—and we turn off output capture so that the log output (truncated to a configurable number of lines) is displayed on the console. By default, if the environment variable `QVSIM_LOGOUT` is not set, your script will output just the first 25 lines of the log file if it’s longer than that.

Update your `meson.build` file as follows:

```meson
project('qvqsim', [],
  version : '0.1',
  meson_version : '>=0.55',
  default_options : ['warning_level=2']
)

# Ensure that a Python3 interpreter is available.
python_dep = dependency('python3', required: true)

# Install Python scripts and configuration files.
install_data(
  'qvqsim.py',
  'qv_simulate.py',
  'input_qvqsim.py',
  'input_json.py',
  'input_yaml.py',
  'output_qvqsim.py',
  'config.toml'
)

# Custom target to run the 'doit.sh' script.
# The doit.sh script should:
#   - execute the simulator and write its log file (with an auto-incremented name)
#   - check the line count of the log file and output either the entire file or a
#     truncated version (25 lines by default, or ${QVSIM_LOGOUT} lines if that env var
#     is defined)
#   - touch a marker file (here, doit.stamp) so that Meson has a stable output.
doit_run = custom_target('doit_run',
  command : ['./doit.sh'],
  output  : 'doit.stamp',       # a dummy file produced by doit.sh via "touch doit.stamp"
  build_by_default : true,
  build_always : true,         # always run this target so the log output is processed each time
  capture : false              # pass the output directly to the console
)

# Alias target so that running "ninja doit" executes our custom target.
alias_target('doit', doit_run)
```

### Updating your `doit.sh` Script

Make sure your `doit.sh` (which is invoked by the custom target) is modified to:

1. Determine the next log file name (e.g., `doit_log_001.txt`, etc.).
2. Run the simulator so that all stdout and stderr are redirected to that log file.
3. Check the line count of the log file and output either the full file if it has fewer than the target number of
   lines or, if it exceeds, output only the top N lines where N defaults to 25 or is overridden by the
   environment variable `QVSIM_LOGOUT`.
4. Touch a file (here, `doit.stamp`) so that the target always produces its output.

Below is an example `doit.sh` reflecting these points:

```bash
# Remove any shebang since this file is intended to be sourced by custom_target if needed.

# Define file name parts.
log_prefix="doit_log_"
log_suffix=".txt"

# Look for existing log files matching the pattern.
existing_logs=( ${log_prefix}[0-9][0-9][0-9]${log_suffix} )
next_num="001"
if [ -e "${existing_logs[0]}" ]; then
    max=0
    for logfile in "${existing_logs[@]}"; do
        num=$(basename "$logfile" "$log_suffix")
        num=${num#${log_prefix}}
        num=$((10#$num))
        if (( num > max )); then
            max=$num
        fi
    done
    next=$(printf "%03d" "$((max + 1))")
    next_num="$next"
fi

# Compute the new log file name.
log_file="${log_prefix}${next_num}${log_suffix}"

# Run the quantum simulator and redirect stdout and stderr.
python qvqsim.py path/to/input_file > "$log_file" 2>&1
echo "Output logged to $log_file"

# Determine the maximum number of lines to output.
max_lines=${QVSIM_LOGOUT:-25}

# Count the lines in the log file.
line_count=$(wc -l < "$log_file")
if [ "$line_count" -le "$max_lines" ]; then
    cat "$log_file"
else
    head -n "$max_lines" "$log_file"
fi

# Touch a dummy stamp file to satisfy the custom target output.
touch doit.stamp
```

### How It Works

- **Meson Build File:**  
  The `meson.build` file installs your project files and defines a custom target that always
  runs (`build_always: true`). Setting `capture: false` ensures that the output generated by
  `doit.sh` (including the log file processing) is printed directly in the console.

- **Configurable Log Output:**  
  In the script, `max_lines` is set to `$QVSIM_LOGOUT` if defined, otherwise it defaults to 25.
  The script then prints either the entire log file (if it has fewer than or equal to the target
  number of lines) or only the first N lines if longer.

- **Alias Target:**  
  The `alias_target('doit', doit_run)` line lets you run the target with:
  ```bash
  ninja -C builddir doit
  ```
  This will re-run your script each time and display the log output appropriately.

With these changes, running `ninja -C builddir doit` will (a) always cause `doit.sh` to run, and
(b) display your log output trimmed to 25 lines by default, unless you override with `export QVSIM_LOGOUT=<N>`.
