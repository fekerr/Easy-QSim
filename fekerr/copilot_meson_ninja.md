Below is some detailed background information on both the **meson.build** and **build.ninja** files, which are central to configuring and running projects that use the Meson build system with Ninja as its backend.

---

### What Is `meson.build`?

The `meson.build` file is the main configuration file for a project that uses Meson. It is written in a simple, declarative syntax that allows you to specify:

- **Project Metadata:** You can define the project name, version, and the programming languages involved.
- **Build Options:** Global build parameters such as warning levels or optimization flags can be set here.
- **Targets and Build Rules:** This file outlines which source files to compile, what libraries to link against, and how to package or install output files. For example, in our project skeleton, the `meson.build` file uses an `install_data()` function to indicate which scripts and configuration files should be installed.
- **Subdirectories and Dependencies:** Meson supports subprojects and external dependencies. One can include other `meson.build` files from different directories to break the project into modular components.

Because the syntax is easy to read and modify, developers can quickly adjust build parameters or add new targets without wrestling with lower-level build intricacies. Once you run the Meson setup command (e.g.,
```bash
meson setup builddir
```  
Meson reads the `meson.build` file, validates its configuration, and then generates the appropriate backend build files.

---

### What Is `build.ninja`?

The `build.ninja` file is not usually written or maintained by developers by hand. Instead, it is automatically generated by Meson (or other systems that target Ninja) from the high-level instructions found in the `meson.build` file. Its key roles include:

- **Defining Build Rules:** The file contains low-level commands, which are exact recipes Ninja executes to build targets. Each rule typically specifies a command line (like compiling a source file or linking object files) and a description for logging purposes.
- **Tracking Dependencies:** `build.ninja` explicitly tracks what depends on what, which facilitates fast incremental builds. If a source file changes, Ninja knows exactly which steps to rerun.
- **Optimizing Build Performance:** Ninja is known for its minimal overhead. It is designed to be extremely fast and to scale well in projects with many small build steps.

Even though the skeleton provided for our project includes a manually created `build.ninja` file (mainly to illustrate how you might introduce custom build rules, such as running the simulator), it is generally best to let Meson generate this file. That way, it accurately reflects the project’s configuration as specified in `meson.build`.

For example, our skeleton `build.ninja` includes a simple rule:
```ninja
rule run_simulator
  command = python qvqsim.py $in
  description = Running quantum simulator for $in

build run: run_simulator qvqsim.py
```
This rule serves as a minimal example that demonstrates how a custom command may be defined. In practice, after configuring your project with Meson, the generated `build.ninja` will be much larger and include all necessary compilation, linking, and custom build steps based on your configuration.

---

### In Summary

- **Meson.build:**  
  - A high-level configuration file written in a straightforward syntax.  
  - Defines project metadata, build parameters, targets, and rules.  
  - Simplifies configuring complex projects while abstracting away platform-specific details.

- **Build.ninja:**  
  - A low-level build file generated by Meson that Ninja executes.  
  - Contains explicit commands and dependencies for fast, incremental builds.  
  - Typically managed by Meson, so developers rarely have to edit it manually.

Using Meson with Ninja allows you to enjoy a modern and efficient build process that separates high-level project setup from the rapid, low-level task execution done by Ninja.
